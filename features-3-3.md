# New in 3.3
{: .no_toc }

System health and security: one overview page, which job blocks which, what is close to an IBM i limit, a security score, the security audit journal hour by hour, the disk units of each ASP, the statistics of the SQL inside your programs, and VS Code tasks that run on the IBM i.
{: .fs-6 .fw-300 }

{: .note }
> **Coming in version 3.3.0.** These pages are in the source on GitHub and will be on the Marketplace with the 3.3.0 release. The pictures are drawn with Vanthrex's own code and sample data; in VS Code each page is interactive.

## System Health Overview

One page that answers *"is the system OK right now?"*: disk space per ASP, limits close to their maximum, jobs waiting for a lock, jobs waiting for a reply (MSGW) and the security score, each as a card with a traffic light and a button to its detail page.

**Open it:** **System Health Overview (Visual)** from the command palette or the quick menu (`Ctrl+Alt+I`).

**What you can do:**
- Read the overall status at the top: *Everything looks fine*, *Some things are worth a look* or *Something needs attention now*.
- Click **Open …** on a card for the detail page: Disk Units Map, Limits Watch, Lock Wait Chains, Active Jobs Map or Security Scorecard.
- Tick **Refresh every minute** to keep it on a second screen.
- Each card is read on its own: a card you are not authorized to read says why, and the others still work.

| Card | Orange | Red |
|---|---|---|
| Disk space | an ASP at 80 % used, or its units filled unevenly | an ASP at 90 % used |
| Limits | a limit at 75 % of its maximum | a limit at 90 % |
| Lock waits | a job waiting for a lock | 5 jobs waiting, or one job blocking 3 or more |
| Messages waiting | — | any job waiting for a reply (MSGW) |
| Security | score below 75 | score below 60 |

## Lock Wait Chains

Which job blocks which, right now: every object and row a job waits for, with the jobs holding it on one side and the jobs waiting on the other. The **head blocker** (👑) holds a lock others wait for and waits for nothing itself — usually the job to look at.

## VS Code tasks for IBM i

A `vanthrex` task type for `.vscode/tasks.json` that runs a CL command (with extra libraries on the library list) or a PASE command (in an IFS folder) over the connection, with the Code for IBM i style variables `&CURLIB`, `&USER`, `&HOST`, `&NAME`, `&EXT`, `&FILENAME` and `&RELATIVEPATH`.

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Compile this RPG from the IFS",
      "type": "vanthrex",
      "kind": "cl",
      "command": "CRTBNDRPG PGM(&CURLIB/&NAME) SRCSTMF('/home/&USER/src/&FILENAME') DBGVIEW(*SOURCE)",
      "libraries": ["APPLIB", "UTILLIB"],
      "problemMatcher": []
    },
    {
      "label": "Build with makei",
      "type": "vanthrex",
      "kind": "pase",
      "command": "makei build",
      "cwd": "/home/&USER/myproject"
    }
  ]
}
```

**Run it:** **Terminal → Run Task…**; Vanthrex also offers ready-made tasks (compile RPG from the IFS, build with makei, show the library list). The output appears in the terminal panel.
