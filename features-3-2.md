**Open it:** right-click a library → **Library Space Map**, or **Library Space Map (Visual)…** from the command palette or the quick menu (`Ctrl+Alt+I`).

**What you can do:**
- **Colour by last used:** green used this month, yellow up to 6 months, orange up to a year, red over a year. An object never used is counted from the day it was created.
- **Type to highlight** objects by name, type or text; **click a kind** in the legend to hide it.
- **Click a tile** for the object information (size, owner, journaling, locks…).
- Under the map: the total size, the number of objects, the biggest kind, the space not used for a year and the 15 largest objects.

{: .note }
> Typical use: before a clean-up, a save or a migration — the old save files and journal receivers are usually the first big red tiles.

**Open it:** **Batch Job Timeline (Visual)** from the command palette or the quick menu.

**What you can do:**
- Jobs that **overlap** get their own lane, so you see what ran at the same time.
- **Filter** by job name (`ORD*` for every job starting with ORD) or by user. Only `*` is a wildcard: `ORD_EXT` matches that job only.
- **Click a bar** for the job log; **right-click** for the run history of that job.
- Tiles show the runs, the jobs that ended abnormally, the jobs still running, the longest run and the CPU used; the failed and the longest runs are listed below.

Advice for the same table whose keys start the same way is merged: an index on `(CUSTNO, ORDDATE)` also serves the queries that asked for `(CUSTNO)` — here it *covers 2* pieces of advice. **CREATE INDEX…** writes the statement into an SQL editor:

```sql
CREATE INDEX APPLIB.ORDERS_IX1 ON APPLIB.ORDERS (CUSTNO, ORDDATE);
CREATE ENCODED VECTOR INDEX APPLIB.ORDHIST_EVI2 ON APPLIB.ORDHIST (STATUS);
```

**Open it:** right-click a library → **Index Advice Chart**. Nothing is created until you run the SQL; check large, busy tables first, since an index speeds up reads and slows down writes.
